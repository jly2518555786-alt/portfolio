##我的故事

我最早感受到 AI 浪潮，不是在新闻里，而是在行业会展中。

关注到 PE/VC 正在全力押注 AI 行业，参加了 WAIC 人工智能大会之后，这更让我确信了我未来发展的方向。

AI 不是一个等待研究的遥远趋势，它已经开始重新定义每个人的工作方式。秉持着知行合一的观点，我没有停留在观察和讨论层面，而是直接开始学习和使用 **Codex**、**Gemini** 等大模型。

最初的感受非常直接——**爽**。

过去需要反复沟通、检索和执行的工作，现在居然可以被如此迅速拆解和推进；过去停留在脑海里的所有天马行空的产品想法，也可以通过 **Vibe Coding** 快速做出原型。

但当我真正开始搭建产品、构建 **Agent Skills** 时，我很快发现：AI 可以大幅降低写代码的门槛，却不会替代对计算机系统的理解。诸如此类的问题在我的脑中涌现：

* 后端数据库怎么搭建？
* 提示词怎么优化？
* Context engineering 怎么做？
* 该如何为 AI 创造出一个更好的环境？

越想让 AI 做复杂的事情，就越需要知道软件究竟是怎样运转的。因此，我开始沿着第一性原理向下追问：一个完整的软件产品由哪些部分组成？前端、后端、数据库、接口和部署之间如何协作？Agent 为什么会失败？模型的能力边界在哪里？

为了回答这些问题，我沿着全栈工程师的知识体系持续补课，也开始阅读计算机史和计算机科普书籍。这个过程让我发现，计算机科学真正迷人的地方，不只是“能做出一个产品”，而是人类如何把复杂问题一层层抽象，最终变成可以执行的系统。

同时，越往下深挖，越发现应用 AI 的能力居然和人文社科的底层能力是互通的：

* **Skill** 其实就是分类学
* **Prompt** 其实就是语言学
* **Context** 其实就是信息科学
* **多 Agent 协同** 其实就是管理学
* **LOOP engineering** 核心能力是目标定义和管理

至此，人类社会的文理能力在 AI 产品上交汇，知识和真理，到最后必然是融会贯通的。

我对 AI 的热情，也不只停留在“看好 AI”。我更希望亲手使用它、理解它、构建它，并通过一个个真实作品检验自己的判断，然后无限地去追求真理。

目前，我利用 AI 完成的项目 demo、产品探索和 Skills 实践，都记录在我的简历和个人 GitHub 主页中。它们未必成熟，但每一项都是我真实做过、踩过坑、迭代过的东西。

欢迎各位老师查看和指点。对我来说，真正有意思的事情才刚刚开始。。
